# Подключение к Omarchy

Набор сохраняет модули, а не полный персональный конфиг. Первое подключение
требует точечного согласования с уже зарегистрированными биндами и shell.json.
Сборщик создаёт проверяемое дерево файлов; автоматически активного сеанса не касается.

## Последовательность

1. Собрать и осмотреть stage. Сохранить текущие собственные файлы перед заменой.
2. Установить `.so` в `~/.local/lib/hyprland-plugins/` через временный файл и
   атомарный rename. Никогда не перезаписывать inode загруженной библиотеки.
3. Скопировать требуемые модули из `hypr/` в `~/.config/hypr/`. `monitors.lua`,
   `input.lua`, основной `hyprland.lua` и пользовательские bindings целиком не заменять.
4. Загружать `require("hypr.virtual-desktops")`, затем `require("hypr.overview")`.
   После штатных defaults вызвать `require("hypr.virtual-desktops").bindings()`
   ровно один раз. До регистрации defaults исключить прежние workspace-бинды
   через обёртку `o.bind`. Не добавлять вторую копию тех же сочетаний.
5. В той же обёртке до регистрации заменить Win+S на
   `python3 ~/.config/hypr/scratchpad-control.py toggle`, а Win+Alt+S — на
   `python3 ~/.config/hypr/scratchpad-control.py stash` (при передаче через shell
   использовать развёрнутый, корректно экранированный абсолютный путь).
6. Для Win+C/V/X заранее заменить stock handlers функциями copy/paste/cut из
   `require("hypr.clipboard")`. Win+Ctrl+V остаётся открытием истории.
7. Подключать пользовательские QML-плагины через штатное управление Omarchy;
   проверить соответствующие entryPoints и собственный shell.json. Идентификаторы
   `idefant.*` сохранены для совместимости с уже установленной конфигурацией.
8. Загрузить cursor-redraw-fix из `input.lua`, сохранить
   `cursor.no_warps=false`, `warp_on_change_workspace=1`,
   `hide_on_key_press=true`, `no_hardware_cursors=2` (auto).
9. `hyprctl reload`, затем `hyprctl configerrors`. Проверить **реально загруженные**
   версии через `hyprctl -j plugin list`; reload не заменяет уже загруженную `.so`.
   Для новой библиотеки нужна штатная замена плагина либо новый вход.

Не выполнять диагностический `hl.unbind` или `:unbind` в активном сеансе и не
обращаться к handles удалённых биндов. Для существующих собственных handles
использовать предусмотренный приложением `set_enabled(false)` либо менять
регистрацию в исходной конфигурации до загрузки defaults.

## Что проверять

- Столы 1–9 переключаются на всех экранах. Фокус браузера по ссылке тоже меняет
  общий стол. Отключённый экран не делает обычные окна недоступными.
- Win+Tab показывает на каждом выходе его собственные миниатюры; Esc/Tab
  закрывают все grids. `hyprctl -j hyprexpostate` показывает текущие native sessions.
- Win+S открывает также пустые группы; ручной перенос между экранами меняет
  место повторного появления. Состояние скрэчпада находится в XDG_RUNTIME_DIR,
  в Git его не сохранять.
- Курсор следует за фокусом и скрывается при печати. Проверить реальные ощущения
  Mouse Modes: присутствие процесса само по себе не доказывает правильную работу.
- Панель должна использовать актуальные QML-файлы: одного reload/наличия файла
  недостаточно. Проверить живой IPC; при необходимости штатно перезапустить shell.

## Отдельные зависимости

- Блокировка использует PAM services `omarchy-lock-password` и
  `omarchy-lock-fingerprint`, fprintd и штатные Omarchy lock helpers. Текущие
  PAM-правила машины в репозиторий не экспортированы. Сначала подтвердить
  работоспособность password flow; модуль не должен подменять системную
  политику аутентификации автоматически. Fingerprint — дополнительная возможность.
- В терминале VS Code текстовая вставка должна вызывать
  `workbench.action.terminal.paste`, а Ctrl+Alt+V отправлять `\\u0016` через
  `workbench.action.terminal.sendSequence` для вставки изображения в CLI.
  Эти настройки приложения не применяются сборщиком и не заменяют редакторские бинды.
- Геометрия/масштаб/порядок конкретных мониторов и имена XKB-раскладок относятся
  к персональным настройкам. Для clipboard.lua зафиксированы физические XKB-коды
  стандартных US/русских буквенных слоёв; Dvorak/AZERTY требуют пересмотра кодов.
- Аппаратный курсор и Hyprspace не входят в этот набор. Прежние неудачные пробы
  не повторять автоматически; это независимые изменения пользовательского поведения.

## Откат

Возвращать только изменённые собственные модули и строки подключения из сохранённой
копии. Для обзора можно вернуть действие Win+Tab
`omarchy-shell shell toggle idefant.workspaces`, убрать require hypr.overview,
reload/check errors и лишь затем выгрузить hyprexpo. Панель и virtual-desktops
могут остаться. Не сбрасывать весь пользовательский конфиг ради отката компонента.

## Тестовые сеансы

Полные runtime-тесты находятся в двух внешних форках. Они создают вложенный
Hyprland обычным видимым окном. Для этой машины **всегда** обеспечить появление
этого окна сразу на общем столе 9 основного сеанса, без смены стола и фокуса
пользователя. Поздний перенос уже сдвигает рабочие окна и недостаточен.
Если размещение заранее гарантировать нельзя, тест не запускать. Наличие
простого standalone теста upstream ещё не означает выполнение этого требования.
Набор не запускает compositor при сборке, check, stage или создании архива.
