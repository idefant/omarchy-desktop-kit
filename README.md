# Omarchy Desktop Kit

Наши расширения Omarchy/Hyprland, собранные в один набор с закреплёнными
зависимостями. Личные настройки машины остаются в её конфигурации и Restic/S3.

| Модуль | Назначение |
| --- | --- |
| `hypr/desktop-control.py`, `virtual-desktops.lua` | общие столы 1–9, перемещение окон, поиск пустого стола, проверка раскладок |
| `hypr/scratchpad-control.py` | общий скрэчпад на всех экранах, последнее расположение окон, fallback отключённого экрана |
| `hypr/overview.lua` | нативный Win+Tab через наш hyprexpo |
| `native/cursor-redraw-fix` | устранение двойников курсора при переносе и скрытии во время печати |
| `plugins/idefant.workspaces` | индикатор общих столов; прежний QML-обзор оставлен для отката |
| `plugins/idefant.clipboard`, `hypr/clipboard.lua` | история и вставка, включая US/русскую раскладку и терминалы |
| `plugins/idefant.lock` | собственный экран блокировки с раздельными PAM-потоками |
| `plugins/idefant.battery` | собственная служба уведомлений батареи |

## Сборка одного набора

Проверенное окружение: Hyprland 0.56.2 (точный commit в `sources.lock.json`),
пакет Omarchy 4.0.4-1, Quickshell 0.3.1-1. Нативные плагины требуют совместимого
ABI. Для другой версии Hyprland сначала нужны пересборка и проверка всей связки.

Нужны Python 3, Git, CMake, C++ toolchain, pkg-config, заголовки Hyprland и его
зависимостей, Lua, Pango/Cairo. Исполняемые зависимости: Omarchy shell/Quickshell,
`hyprctl`; для буфера — штатные Omarchy clipboard helpers, wl-clipboard и jq.

```sh
python3 scripts/kit.py check
python3 scripts/kit.py build --output /tmp/desktop-kit-build
python3 scripts/kit.py stage --build-dir /tmp/desktop-kit-build --dest /tmp/desktop-kit-stage
python3 scripts/kit.py archive --stage /tmp/desktop-kit-stage --output /tmp/omarchy-desktop-kit.tar.gz
```

`build --sources-root ~/Projects/work/system` использует локальные Git-копии
двух форков для создания отдельных checkout в каталоге сборки. Исходные проекты
не меняются. Коммиты всё равно берутся из lock-файла. В обычном режиме зависимости
клонируются с GitHub. Все три `.so` собираются вместе; build.json фиксирует их SHA256.

`stage` создаёт дерево файлов относительно HOME. Он проверяет совпадение сборки
с lock-файлом и хэши библиотек и отказывается перезаписывать непустой каталог.
Команды не запускают compositor, не регистрируют бинды, не меняют настройки,
не загружают `.so` и не читают буфер обмена.

Это исходники и сборщик набора с проверяемым архивом. Нативный пакет pacman и
автоматическая миграция действующих пользовательских конфигов пока не реализованы.
Не распаковывать архив вслепую поверх HOME: см. [подключение](docs/integration.md).

## Два внешних форка

- [idefant/hyprland-virtual-desktops](https://github.com/idefant/hyprland-virtual-desktops/tree/feature/overview-bridge)
  управляет принадлежностью окон, синхронным переключением, hotplug и внешним фокусом.
- [idefant/hyprexpo](https://github.com/idefant/hyprexpo/tree/feature/shared-desktop-overview)
  сохраняет нативную отрисовку обзора и получает раскладки через bridge первого плагина.

Их исходники не скопированы в этот репозиторий. Коммиты закреплены в lock-файле.
Обновление набора означает проверку совместимых версий вместе и затем изменение
lock-файла. Одного `hyprctl reload` для замены уже загруженной библиотеки недостаточно.

## Границы и сохранность

В репозитории нет мониторов/серийных номеров, раскладок конкретного пользователя,
полного `hyprland.lua`, `shell.json`, паролей, истории буфера, оконных дампов,
данных приложений, старых `.bak` и готовых бинарников. `idefant.*` — идентификаторы
наших плагинов, не автоматически переименованные штатные плагины.

Существующая конфигурация уже сохраняется в зашифрованный Restic/S3; этот
репозиторий сохраняет переносимый исходный код и сборку. Отдельный dotfiles-репозиторий
для резервного копирования настроек не требуется. Создание набора само по себе
не включает новые пути в Restic и не меняет расписание копирования.

Проверки поведения общих столов и обзора находятся в двух форках
(`tests/hotplug.py`, `tests/shared_desktops.py`). Они запускают **вложенный Hyprland
обычным видимым окном**, не виртуальную машину. Их следует запускать отдельно:
обычная проверка/сборка набора этого не делает. Инвентаризация исходников —
`inventory.json`; изменения файлов нужно явно отразить в ней.
